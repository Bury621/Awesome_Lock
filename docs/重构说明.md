# Awesome Lock v2.0 重构说明

本文记录旧版固件“经常卡死”的根因、重构后的架构、逐项修复清单，以及烧录前必须注意的行为变化。

> 旧文件已在本仓库中删除，但都保存在 git 的首次提交里，可随时查看：
>
> ```powershell
> git show HEAD:Service/UserInterface.c
> git show HEAD:Service/multi_timer.c
> git show HEAD:Hardware/lcd_menu.c
> ```

---

## 1. 结论：为什么会卡死

旧版不是某一个 bug，而是**多个“在中断里做阻塞操作”的问题叠加**。核心链路如下：

1. `Core/Src/stm32f4xx_hal_msp.c` 里把中断分组设成了 `NVIC_PRIORITYGROUP_0`（4 位全部是子优先级），所有中断处于**同一抢占级**。这意味着 **SysTick 无法抢占任何一个 ISR**。
2. 按键 EXTI 中断里直接调用 `Service_KeyboardHandler()`，它会调用：
   - `HAL_I2C_Master_Receive(..., 100)`；
   - `LCD_Clear()` / `LCD_ShowString()` 等整屏绘制；
   - 密码错误时调用 `Verify_fail_publish()`。
3. `Verify_fail_publish()` 用 `for (x=0; x<FAIL_LOCK_TIME; x++) { 喂狗; 1680 万次 __NOP; }` 死等约 **10 分钟**，而且是在 EXTI 中断里。
4. HAL 的 `HAL_I2C_Master_Receive` / `HAL_UART_Receive` 超时依赖 `HAL_GetTick()`，而 `HAL_GetTick()` 靠 SysTick 递增。SysTick 被同级 ISR 挡住 → tick 不增长 → **超时永远不触发** → 等不到应答时 HAL 永远不返回。
5. 看门狗只在 TIM4 中断里喂，TIM4 同样是同一抢占级，也被 EXTI 挡住 → 约 5 秒后 IWDG 复位；如果 EXTI 里还在死循环，就表现为“屏幕定住/反复重启”。

其他独立的卡死/异常来源：

| 位置（旧版） | 问题 | 后果 |
| --- | --- | --- |
| `Hardware/Keyboard.c:15` | I2C 读失败直接 `Error_Handler()`，内部 `__disable_irq(); while(1)` | 一次总线干扰就永久卡死，直到看门狗复位 |
| `Hardware/Fingerprint.c:32-34` | 连续 3 次 `HAL_UART_Receive(..., 2000)`，且不检查返回值 | 指纹无应答时在中断里卡 6 秒 |
| `Hardware/Fingerprint.c:178` | 注册时 `HAL_UART_Receive(..., 100000)` | 最长阻塞 100 秒 |
| `Service/UserInterface.c:159` | `Show_regist_FPG_interface()` 在按键处理中直接调用阻塞注册 | 注册流程整个跑在 EXTI 里 |
| `Service/multi_timer.c:58` | 定时器回调在 TIM7 中断里执行，回调里会 `Show_main_interface()` 整屏重绘 | 中断里刷屏，阻塞其他中断 |
| `Hardware/lcd.c` | 每个像素单独 `HAL_SPI_Transmit` + 翻转片选 | 整屏清屏几十万次 GPIO/SPI 调用，耗时上百毫秒 |
| `Core/Src/stm32f4xx_it.c:227` | `EXTI9_5_IRQHandler` 里清的是 `Led2_Pin`（PA7），不是霍尔 PE7 | EXTI line7 挂起位可能清不掉，存在中断风暴风险 |
| `Service/UserInterface.c:598` | 锁定用双重 `for` 空转，期间只喂狗 | 主循环/界面/按键全部停摆 10 分钟 |

> 总结：**旧版把“读传感器、等串口、刷屏、延时”都放进了中断，并且让 SysTick 无法抢占中断。**
> 只要任何一个外设偶发无应答，整机就会永久等待；看门狗又在中断里喂，无法纠正。

## 2. 新架构

```
中断（EXTI0 / EXTI9_5 / UART5 / TIM6）
        │  只做：清标志、投递事件、搬字节、电机走一步
        ▼
AppEvent 环形队列（16 条）
        ▼
主循环 App_Running()
   ├─ LockApp_HandleEvent()   按键/指纹触摸/人体感应事件
   ├─ FPC_Poll()              指纹协议解析、超时、延迟灯光
   ├─ LockApp_Poll()          按键去抖、密码状态机、开关门、倒计时、休眠
   └─ HAL_IWDG_Refresh()      主循环存活才喂狗
        ▼
UI 层逐点直接写屏（与旧版相同，绘制只发生在主循环）
```

### 2.1 中断优先级

`HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4)`，抢占优先级：

| 中断 | 抢占优先级 | 说明 |
| --- | --- | --- |
| SysTick | 0 | 保证 `HAL_GetTick()` 永远在走，HAL 超时可靠 |
| TIM6 | 1 | 步进电机节拍 |
| UART5 | 2 | 指纹接收 |
| EXTI0 / EXTI9_5 | 3 | 按键、指纹触摸、人体感应、门磁 |

EXTI 里只调用 `AppEvents_PushFromISR()`，不做任何外设访问。

### 2.2 文件结构

| 新文件 | 作用 | 替代的旧文件 |
| --- | --- | --- |
| `App/app_events.c/.h` | 中断 → 主循环事件队列 | — |
| `App/app_util.h` | 临界区、回绕安全的时间比较 | — |
| `App/App.c/.h` | 初始化、主循环调度、中断回调 | 旧 `App.c` |
| `Service/lock_app.c/.h` | 门锁业务状态机 | 旧 `Service/UserInterface.c` |
| `Service/ui_views.c/.h` | 纯界面绘制 | 旧 `UserInterface.c` 的 Show_* + `lcd_menu` |
| `Hardware/Fingerprint.c/.h` | 非阻塞指纹协议 | 旧 `Fingerprint.c` |
| `Hardware/Keyboard.c/.h` | 容错 I2C 读键 + 总线恢复 | 旧 `Keyboard.c` |
| `Hardware/flash_eeprom.c/.h` | 带 CRC 的密码存储 | 旧 `flash_eeprom.c` |
| `Hardware/stepper_motor.c/.h` | 修正速度单位、并发保护 | 旧 `stepper_motor.c` |
| `Hardware/lcd.c/.h` | 恢复旧版逐点直写 + 修复越界 | 旧 `lcd.c` |

已删除（不再参与编译）：`Service/UserInterface.*`、`Service/multi_timer.*`、`Hardware/lcd_menu.*`。
Keil 工程（`.uvprojx`）与 EIDE 工程（`.eide/eide.yml`）都已同步更新。

## 3. 逐项修复清单

### A. 卡死 / 复位

1. **中断里不再做任何阻塞操作**：EXTI 只投递事件；UART 接收中断只逐字节喂解析器；TIM6 只走一步电机。
2. **中断分组改为 GROUP_4**，SysTick 最高优先级，HAL 超时恢复有效。
3. **删除 10 分钟空转锁定**：改为 `s_lockout_until` 截止时间，主循环每秒刷新倒计时，期间界面/按键/看门狗全部正常。
4. **指纹驱动重写为非阻塞**：
   - UART5 接收中断 + 环形缓冲 + 滑窗找包头；
   - 校验长度、校验和，错帧自动丢 1 字节重新同步；
   - 完整帧放入队列，`FPC_Poll()` 在主循环处理；
   - 验证 3 秒、注册 20 秒、清库 3 秒超时，全部非阻塞；
   - 补上了旧工程缺失的 `UART5_IRQHandler`。
5. **按键读取移出中断**：EXTI 只置事件，25ms 去抖后主循环读 I2C；失败重试 + 9 个时钟脉冲总线恢复，不再 `Error_Handler()`。
6. **看门狗只在主循环喂**，超时放宽到约 10 秒（覆盖 Flash 擦除）。
7. **显示移出中断**：所有 `UI_*` 只在主循环调用。
8. **修正 EXTI9_5 的 line7**：由错误的 `Led2_Pin` 改为真正的 `Hall_IRQ_Pin`（PE7），避免挂起位清不掉。
9. **多定时器删除**：原来的 `MultiTimer` 只有一个实例，开门定时、LED 定时会互相覆盖；新版统一用 `HAL_GetTick()` 截止时间，互不影响。

### B. 内存越界 / 潜在 HardFault

1. `pwd[]` 满 32 字节时没有 `'\0'`，`strcmp` 会越界读；新版缓冲区 33 字节、最多输入 31 位、每次追加都补 `'\0'`。
2. `Service_clear_inputed_pwd()` 只清 31 字节；新版 `memset` 整个缓冲区。
3. `Service_get_real_pwd()` 可能返回 `NULL`，随后 `Service_cmp_pwd()` 直接解引用；新版 `FLASH_EEPROM_GetPassword()` 永远返回有效字符串。
4. `LCD_ShowChar()` 对非 ASCII 字符直接查表越界；新版限制在 `' '..'~'`，非法字符显示 `?`。
5. `LCD_ShowNum()` 在位数大于显示宽度时下标下溢；已修正。
6. `LCD_ShowBedImage()` 使用 `gImage_bed + 12`，但该数组是 **8 字节头 + 48×48×2 数据 = 4616 字节**，旧代码越界读 4 字节且整体像素错位；已改为 `+8`。
7. 指纹接收缓冲区未初始化/不检查 `HAL_UART_Receive` 返回值；新版不再使用固定长度阻塞接收。
8. `FPC_Get_Registed()` 错误返回值写成 `0xFFFFFF`（应为 32 位）；新版直接按索引表位图取空闲 ID。
9. Flash 写入判断 `strlen(pwd) > PWD_MAX_LEN` 存在 off-by-one；已改为 `length >= PWD_MAX_LEN` 拒绝。
10. `uart_printf()` 使用 `vsprintf` 写 128 字节缓冲区，长字符串会溢出；改为 `vsnprintf`。
11. `sprintf` 生成错误码文本改为 `snprintf`。

### C. Flash / 数据可靠性

1. 旧版存储地址 `0x0800C000`（Sector 3 起始）只有 16KB；当前固件已经约 37.6KB，**再增长就会擦掉自己**。新版改到 `0x08020000`（Sector 5，128KB），固件可用空间 128KB。
2. 存储记录增加：魔数、版本、长度、CRC32。空白 Flash、掉电写坏、旧格式数据都会自动回退默认密码，而不是把 `0xFF` 当密码。
3. 擦除/编程前后加解锁、错误标志清理、回读校验；整个过程中关中断并提前喂狗。
4. 看门狗周期放宽到 10s，覆盖 128KB 扇区最坏擦除时间。

### D. 电机 / 门控

1. TIM6 由 2µs 计数改为 **1µs 计数**，`step_us` 参数终于等于真实微秒；`OPEN_DOOR_STEP_US = 980` 保持旧版实际速度（旧 490×2µs）。
2. `StepperMotor_SetSpeed()` 以前只在电机运行时写 ARR，导致第一步仍用旧速度；现在总是更新。
3. 电机状态更新加临界区，避免主循环与 TIM6 中断竞争。
4. 开门/关门增加“运行中请求排队”和“到位后保持扭矩”，避免在电机转动中反向造成丢步。
5. 开门后保持扭矩、超时自动关门、关好后再返回主界面，逻辑不再依赖 `have_keep_pos` 全局变量。

### E. 指纹协议安全

1. 灯光指令的确认包与验证确认包在协议上无法区分。若刚发完灯光就发验证，灯光 ACK 可能被误判为“验证通过”。
   - 新版在每次灯光指令后设置 **150ms 保护窗**，窗口内拒绝启动验证/注册/清库；
   - 触摸事件会延迟 200ms 自动重试一次，不会丢失；
   - 灯光请求在模块忙时排队，避免 ACK 串包。
2. 指纹连续失败达到阈值后，仅禁用指纹并要求密码，**不会**把整机锁死 10 分钟（防止路人乱按造成拒绝服务）；密码验证成功后自动恢复指纹。
3. 取消注册/清库不再允许，避免模块迟到的应答串到下一次操作；最长等待 20 秒后自动超时。

### F. 界面 / 交互

1. **显示路径已回滚为旧版逐点直写**：实机反馈新 LCD 帧缓冲/批量 SPI 版本出现中文异常和重启后，为优先保证可用性，恢复与旧版一致的绘制方式；`LCD_Flush()`/`LCD_FlushArea()` 保留为空函数，UI 代码不用改。绘制仍然只在主循环执行，不会在中断里刷屏。
2. 修正文字自动换行导致的重叠：所有提示字符串控制在 15 个字符以内。
3. 锁定界面显示剩余秒数；密码错误显示提示；注册/清库显示结果和错误码。
4. 休眠时间恢复为配置的 10 秒（旧版 TIM2 每 10 秒加一，实际约 100 秒才休眠）。
5. 熄屏后第一次按键/触摸只唤醒，不参与输入，避免误触。
6. 管理员菜单保留原来的三项（改密码、注册指纹、清空指纹），但不再使用独立的 `lcd_menu` 模块。

## 3.5 2026-10 实机反馈后的修正

第一次重构版上板后出现「中文显示错误、自动重启、按键无反应」。已做以下修正：

| 问题 | 处理 |
| --- | --- |
| 中文显示异常 | LCD 恢复旧版逐点直写（删除 40KB 帧缓冲/批量 SPI 方案），只保留越界修复；`LCD_Flush()` 变为空函数 |
| 自动重启 | 增加 UART5 错误中断风暴保护：PD2 上拉，1 秒内错误超过 20 次就暂停接收 2 秒，避免主循环被饿死触发 IWDG；PA0（人体感应）改下拉，防止悬空产生 EXTI0 中断风暴；每个 EXTI 源加最小间隔限流 |
| 按键无反应 | I2C 超时从 5ms 恢复到 50ms，按键读取延迟从 25ms 降到 2ms；删除自动 `HAL_I2C_DeInit/Init`（反复初始化可能让按键模块失联） |
| 定位重启原因 | USART1（9600）启动时打印复位原因和初始化阶段；HardFault/Error_Handler 也会打印标记 |

### 用 USART1 定位重启

把 USB-TTL 接到 USART1（PA9/PA10，9600 8N1），上电应看到类似：

```
=== BOOT ===
RESET: Power-on
APP: init start
APP: motor ok
APP: keypad ok
APP: lcd ok
APP: lock ready
```

如果反复重启，最后一行的位置就是卡住/复位的阶段；`RESET:` 行给出复位源：

- `RESET: IWDG`：主循环超过约 10s 没喂狗，说明卡死或被中断饿死；
- `RESET: BOR`：供电跌落，检查电源/背光/电机；
- `RESET: Pin / debugger`：复位脚或下载器；
- `[HARDFAULT]`：发生了硬件异常（内存越界/非法访问）；
- `[ERROR_HANDLER]`：HAL 初始化失败。

如果仍然出现中文异常，请拍一张屏幕照片（注明是哪个界面），因为逐点直写已经与旧版一致，剩下的只可能是字模索引/面板方向问题。

## 4. 行为变化 / 迁移注意

| 项目 | 旧版 | 新版 | 影响 |
| --- | --- | --- | --- |
| 密码存储地址 | `0x0800C000` Sector3 | `0x08020000` Sector5 | **旧密码不沿用**，首次启动密码为 `1234` |
| 密码格式 | 裸字符串 | 魔数+版本+长度+CRC32 | 旧数据自动判为无效 |
| 电机速度参数 | `OPEN_DOOR_SPEED=490`（2µs/计数，实际 980µs） | `OPEN_DOOR_STEP_US=980`（1µs/计数） | 速度不变，参数含义变清晰 |
| 门控时间参数 | `OPEN_DOOR_TIME` 秒 | `OPEN_DOOR_TIME_MS` 毫秒 | 数值改为 2000 |
| 返回主界面参数 | `OPEN_DOOR_RETURN_MAIN_TIME` 秒 | `OPEN_DOOR_HOLD_MS` 毫秒 | 数值改为 4000 |
| 自动休眠 | 实际约 100 秒 | 配置的 10 秒 | 可通过 `SLEEPING_TIME` 调整 |
| 指纹失败 | 红灯常亮，仍可继续按 | 达到阈值后禁用指纹，密码成功才恢复 | 更安全，避免无限试错 |
| 密码错误锁定 | 中断里空转 10 分钟，期间整机假死 | 主循环倒计时 10 分钟，界面/按键/看门狗正常 | 这是本次重构的核心目标 |
| 注册/清库 | 可在过程中按 D 返回 | 等待结果，最长 20 秒 | 避免协议 ACK 串包 |
| 首次按键唤醒 | 唤醒并同时输入 | 只唤醒，不输入 | 防误触 |

## 5. 参数怎么调

全部集中在 `Config/Config.h`：

- `ADMIN_PWD`：管理员密码（编译期常量，改完需重新编译）。
- `DEFULT_PWD`：出厂密码（拼写保持旧工程不变，避免外部引用失效）。
- `PWD_MIN_LEN` / `PWD_MAX_LEN`：密码长度限制（`PWD_MAX_LEN` 含结尾 `\0`）。
- `OPEN_DOOR_ANGLE`：开门角度。
- `OPEN_DOOR_STEP_US`：步进间隔，越小越快、扭矩越小；范围 200~4000µs。
- `OPEN_DOOR_TIME_MS`：开门后自动关门时间。
- `OPEN_DOOR_HOLD_MS`：开门后返回主界面时间。
- `FAIL_LOCK_COUNT` / `FAIL_LOCK_TIME`：密码错误锁定阈值/秒数。
- `FGP_MAX_VERIFY`：指纹失败阈值。
- `SLEEPING_TIME`：主界面熄屏时间（秒）。
- `KEYPAD_DEBOUNCE_MS`：按键去抖。
- `FLASH_EEPROM_BASE_ADDR` / `PASSWORD_FLASH_SECTOR`：密码存储位置。
- `MOTOR_REVERSE`：电机方向反转。

> **重要**：`FLASH_EEPROM_BASE_ADDR` 必须位于固件末尾之后、且不能和代码区重叠。
> 当前固件约 49.2KB，Sector5 从 128KB 处开始，余量充足；如果你以后把固件做到超过 128KB，
> 必须把存储位置改到更靠后的扇区（Sector 6/7）或外挂 EEPROM。

## 6. 编译验证

本机使用 EIDE 自带的 **Arm Compiler for Embedded 6.22（armclang）** 做了完整验证：

- 所有用户源文件以 `-std=c99 -O2 -Wall -Wextra` 编译，**0 error / 0 warning**（`lcd_font.c` 的 `-Wmissing-braces` 是原字模数组写法，已单独屏蔽，不影响功能）；
- 连同全部 HAL 源文件、启动文件一起 `armlink` 链接成功；
- 链接结果：

  | 项目 | 大小 |
  | --- | --- |
  | Total ROM（Code + RO + RW） | **49.20 KB** |
  | Total RW（RW + ZI） | **3.85 KB** |
  | Flash 存储起点 | `0x08020000`（Sector5，128KB 处） |

- 这只是**编译/链接通过**，不代表硬件行为已验证。上板前请按 [测试清单](测试清单.md) 逐项验证，尤其是：
  - 指纹验证/注册/清库的实际应答格式；
  - 键盘 I2C 读时序与按键映射；
  - 电机方向、角度、保持扭矩；
  - Flash 写入后断电重启密码是否保持；
  - 看门狗在真实故障下能否复位。

## 7. 仍然存在的限制 / 后续建议

1. **密码明文存储**：Flash 里是 ASCII 密码。建议后续改成“盐 + SHA-256/HMAC”存储，只比对摘要；但会涉及密码学库和升级兼容，本次未做。
2. **管理员密码是编译期常量**，无法在设备上修改；建议后续存入同一 Flash 记录。
3. **无 RTC**：锁定倒计时依赖 `HAL_GetTick()`，断电会清零（这是合理的，重启后不延续锁定）。
4. **指纹协议没有事务号**：通过“灯光保护窗 + 单操作串行化”规避 ACK 串包，属于工程折中；如果换用支持事务号的模块可彻底解决。
5. **LCD 逐点刷新较慢**：目前恢复旧版直写，整屏约 100~300ms；若以后确认硬件稳定，可再尝试「按行窗口」或 DMA 优化，但不要再用整屏多行窗口一次写完的方式。
6. **Flash 擦写寿命**：每次改密码擦一个 128KB 扇区，STM32F4 约 1 万次擦写寿命；按宿舍使用频率足够。若要更耐用，可做双扇区轮换/日志式存储。
7. **没有低功耗 STOP 模式**：目前只关背光；如需电池供电，可加 STOP + RTC/EXTI 唤醒。
8. **门磁/霍尔输入目前只投递事件，未参与业务**；如需“门未关好报警”，可在 `LockApp` 里消费 `APP_EVENT_DOOR_SENSE`。
